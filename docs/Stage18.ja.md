# Stage18 — サービス資源の拡張と実ゲーム検証

この文書は開発途中の履歴です。現在の導入範囲、接続数と検証結果は[Release 1.0](Release-1.0.ja.md)を参照してください。以下の有効化停止や未完了の記載は当時の状態を示します。

対象ゲーム版のImmaterialResourceManagerは35種類の資源を持ちます。
最終値・一時値をそれぞれ500×500×35要素に拡張し、38.4mセルの原点を225としました。
既存256×256グリッドは97セルずらして取り込み、元の世界座標を維持します。
公園の探索キューはushort座標へ変更しています。

256フレームの統計周期を維持して、各フレームで1〜2行を処理します。
25万セルを周期内に一度ずつ更新し、35種類の集計・人口による重み・統計反映と
一時値の消去を接続しました。角度計算の256要素配列や255の資源値は変更しません。

保存参加者は17,500,000個のushort値と4本のint配列、1本のlong配列を保存します。
固定長35,000,980バイトの拡張データを、5個の8MiB以下のチャンクと52バイトの
マニフェストへ分割します。標準保存へは256×256の投影を渡します。
地形・資源データとの結び付け、標準投影の照合、SHA-256、欠落・混在の拒否、
都市全体の保存失敗時の全チャンクの巻き戻しを実装しました。

自動検証では実ゲームILの検索座標・配列確保・角度計算・地形ストライド・
シェーダー座標を検査しています。実ゲームからの変換対象は400メソッド／1874命令、
導入入口で集約する対象は448メソッドです。保存・更新の実装を使用したfixture検証も
通っています。Verify.ps1にServiceChecksとゲーム検証用入口のビルドを追加しました。

IntegrationGameは配布用MODとは別の開発用実ゲーム検証入口です。
ゲーム実行ファイルのコピーとデータの接続を専用フォルダに用意し、
保存・設定をartifacts/isolated-game/UserDataへ転送してWorkshopを無効にします。
元のゲームDLLや既存都市を書き換えません。通常の導入入口のCanActivateはfalseのままです。

実Unityで448接続の適用と新規マップの読み込み完了を確認しました。
この試行で、ToolManagerの設定が作成される前の樹木・Prop初期化が
NullReferenceExceptionになる問題を発見し、修正と回帰検査を追加しました。
追加タイルの地形更新コルーチンに9列の計算が残る問題も修正しました。
また、DataSerializerは親のSerializeが戻った後に各Managerを保存するため、
保存用スナップショットの保持範囲をDataSerializer全体に変更しました。
検証入口は追加隅のサービス値を置き、SavePanelで保存し、別プロセスで
再ロードして照合する処理を持ちます。実行結果はintegration.logとunity.logに記録します。
実ゲームで約91MBの専用都市セーブを作成し、プロセス終了後に別プロセスで再ロードしました。
追加隅(10540.8m, 10540.8m)の最終値32123・一時値12345が一致し、実際のCheckResourceでも照合できました。
地形・所有・道路・建物・区画・樹木・Prop・車両・市民・地区・資源・電気・水道・描画の全拡張配列の実サイズも照合しました。
実ゲームのCalculateLocalResources、地区・地形問い合わせ、StatisticsManagerを使った256フェーズ／25万セルの更新が成功しました。
再ロード前後のセーブSHA-256はFFB574B56E6EC7B23C0D55A2F55D90EA95F7E15BB259C9D5A1BE97EB8C5BFD55で一致しています。
検証用入口の保存と再ロードの進行状態も分離し、再ロード検証が保存を開始する競合を防いでいます。
記録はreports/stage18-unity-proof.log、stage18-unity-reload-success.log、stage18-verification.logです。
追加角(9800m付近)で地形を造成し、実際の道路・樹木・Prop・地区を作成、100タイル所有状態と共に保存しました。
別プロセスで道路接続ID、樹木・Propの位置、地区問い合わせ、地形の高さ、100タイル所有が一致しました。
この再ロードで最外周の区画セル参照の範囲外アクセスを発見し、区画・表面セルを0..4799へ制限するフックを追加しました。
同じセーブを修正後に再ロードし、最外周の頂点4800と外側パディングの問い合わせも成功しました。
配置物を含むセーブのSHA-256はF6F2197805F7939F27523603BDB00AA5B1672CCFCB931717474A184AE61753C3で、検証後も一致しています。
記録はreports/stage18-unity-outer-reload-success.logとstage18-unity-outer-reload-engine.logです。
通常入口の導入と追加領域の電気・水道供給、建物・交通の動作の確認を継続しています。MOD全体の完成判定はまだ行っていません。
