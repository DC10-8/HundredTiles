# Stage16: 地区・公園と導入入口

この段階も完成版ではありません。ゲームへの配置・実行は行っていません。

地区と公園をそれぞれ1000×1000セル、19.2mのまま拡張しました。原点は450セルで、旧512×512領域は194セルずらして移行します。照会、塗装、面積集計、政策更新、公園内の建物・道路・樹木・Prop移動を接続しました。色の重み計算に用いる256は維持しています。

4枚のテクスチャと色バッファを拡張し、地区・公園の表示範囲を中心(960,960)、幅19200mに変更しました。購入領域との対応では100セルを1タイルとし、テクスチャ用の座標オフセットを0にしています。タイル数の5→10だけでは50セルずれるため、原点計算だけは別に変換しています。

地区名の半解像度探索は250000位置になります。元のushortによる位置番号をintへ置き換え、満杯を空と取り違えないキューを使いました。名前とアイコンのメッシュ境界も補正するフックを追加しています。

拡張保存は地区・公園の200万セルを含む16000116バイトです。標準保存には512×512の固定スナップショットを渡し、拡張部分は別エントリーで保存します。チェックサム、標準データの指紋、同じ保存セッションの資源データへの結び付きを確認してから復元します。全参加者の検証後、子ManagerのAfterDeserializeより前に実配列へ戻します。

RuntimeプロジェクトにIUserMod入口、全接続の集約、対象DLL・メソッドのハッシュ確認、接続の重複拒否、対象メソッドへの他MODのパッチ検出、自分のパッチだけを解除する適用失敗処理を追加しました。CitiesHarmonyの準備完了後に呼び出します。CanActivate=falseは維持し、登録・適用より前に停止します。この導入経路はビルド済みですが、Unityでの適用・解除は未検証です。

検証内容:

- 地区名: ushortを超える位置番号、250000件の初期キュー、空の地区、非対称の世界原点。
- 保存参加者: 200万セルの往復、標準領域の投影、実配列の同一性維持、破損・保存の取り違え拒否。ゲームManagerはfixtureです。
- 実ゲームIL: 全1000座標と旧512座標、テクスチャと100区画の対応、4枚の寸法、表示中心・マッピング、政策・塗装の重み計算、補間サンプル原点。
- 既存の道路・建物・区画・交通・保存・描画変換の回帰検証。変換カタログは358メソッド、1612命令。
- 実ゲームDLLを.NET CLRでロードして導入入口の398接続先、接続の集約、28個のprivateフィールド引数を照合。有効化拒否がパッチ適用より前に働くことを確認しました。ゲームのManager生成・実行は行っていません。
- Verify.ps1全体が成功し、全ビルドは警告・エラー0でした。地区を含む10個の実serializer ILと20個のヘルパー挿入も確認しました。実行記録はreports/stage16-verification.logです。導入入口のCLR照合はこの実行後に追加し、単独で成功を確認しています。

ゲーム内の保存・再起動・再ロードは未実施です。樹木・Prop等の残る描画・検索、水源・地形・カメラの境界、その他サービス、ゲームモードの確認が必要です。現セッションにはWindows操作に必要なnode_replがなく、ブラウザ操作ツールのネイティブアプリ操作も無効です。ゲーム画面を操作・観察できると確認するまでは、ゲーム内検証を実施済みとは扱いません。
