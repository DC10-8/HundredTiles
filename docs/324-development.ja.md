## 実ゲームで確認した範囲（2026-10-14）

ゲーム1.21.1-f9、専用コピーのゲーム、リダイレクトしたユーザーデータで検証しました。CitiesHarmony / HundredTiles / HyperLoad / LoadTimeRemainingの最小構成です。ユーザーの都市セーブは使用・上書きしていません。

1. 実際のPluginManager/IUserMod入口から324試作パッチを適用。地形2161平方、購入324、ネットワーク・建物540平方、樹木1080平方の初期化に成功。
2. 新規マップAsanu Beachで自然生成が実行され、追加樹木92,806本と水源5個を作成。見た目・流量の十分な検証を意味しません。
3. ネイティブUnlockArea取引で全324区画を解放。
4. 遠端の地形値を入れた実際のSavePanel保存に成功。セーブ272,723,267バイト、SHA-256 A061579F1E1DB337F14FC4D833149049DB9377A6568823F049F327E0C81A3C42。
5. 別プロセスでそのセーブを再ロードし、全324の購入状態と遠端の地形値を確認。入力ファイルのハッシュが変化しないことも確認しました。
6. 最外周タイル内の25,400〜25,700mで、実際のNetToolによる地表道路・線路のプレビューと作成、BuildingToolによる風力発電建物の配置が成功しました。供給APIで投入した電力・水が拡張グリッドと配管に伝播することも確認しました。実発電・取水設備からの継続供給、需要や経路検索を含む都市運転の検証ではありません。

この状態を272,487,427バイトのセーブへ保存（SHA-256 5B92089FD5F28C11B46B8BFD08545A0FF0C08D1CAD5949FD3485A0C85D86A0B4）し、別プロセスからの再ロードで全324区画・遠端地形・道路・線路・建物・供給状態の復元と入力セーブ不変を確認しました。最外周のGPU地形テクスチャとネイティブ詳細地形の高さも一致しました。取得画面で建物・樹木・地形は描画されていますが、道路・線路の路面メッシュの表示が不十分なため、描画対応を完了とはしていません。カメラ範囲と描画グループへの登録は確認でき、遠景ではLOD 6コール、近景では通常15／LOD 1コールが記録されました。近景でも路面の欠けが残るためLODだけの問題とは判断していません。

7. 遠端でネイティブ地形ブラシ編集と全バックアップサンプルの照合に成功。隔離都市内のツールを一時的にエディタ条件にした検査では、Undoが全4,669,921の地形サンプルを復元することも確認しました。ゲーム本体の都市モードではUndo記録を作らないため、都市モードでのUndo提供を確認した結果ではありません。

試作ランタイムはHundredTilesTrialRuntime=trueで明示ビルドし、isolated-test.markerとユーザーデータの隔離パスが一致する場合だけ動作します。通常の324ビルドでは起動しません。

## 100タイルからの移行検査

実際の100タイル保存から書き出した地形・水流・購入状態の拡張データを用い、全1,442,401セルの高さ・ブロックオフセット・水量・汚染・速度と水流フレームを保持して324へ移行しました。元の購入順序を保持した全324区画の論理購入、v2再保存と読み戻し、入力ファイル不変の検査は通過しています。

自然資源のv1→v2移行も実装し、旧569平方の資源セルと10×10キャッシュの保持、新セルの初期化、破損拒否を検査しました。これは都市全体の移行成功ではありません。

2026年10月15日追記：地区・公園の1000平方から1800平方への移行と、サービス資源の500平方から900平方への移行を接続しました。旧データを再配置せず同じ世界座標に保持し、新しい地区セルはゲームの初期値、サービスセルはゼロで初期化します。旧地区の一括保存と旧サービスの分割保存も、既知のサイズに限って読み込みます。地区・公園の全セル、サービスの全35チャンネル、集計値、再保存、チェックサム・バインディング拒否の自動検査が通過しました。100版のChecks・BridgeChecks・UtilityChecksも通過しています。電気水道の508平方から909平方への移行も接続し、旧v1/v2スキーマ、全セルのフィールド、処理キュー、65024容量と高いノードID、追加セルの初期値、破損・旧座標範囲の拒否を検査しました。隔離都市全体の実ゲーム移行結果は次節に記載します。

### 隔離都市全体の100→324移行（2026年10月15日）

既存の隔離都市 `HundredTiles_Startup_Repair_Verification` を324ランタイムで読み込み、旧地形全1,442,401サンプルの保持をネイティブ配列と照合しました。地区・サービス・電気水道を含む読み込みが完了し、全324区画を購入した状態で `HundredTiles_324_Migration_Verification` へ別名保存しました。保存サイズは274,443,462バイト、SHA-256は `8B16FE285032D7481BC915DE0FEB3CB4C062AA27B696A2ECEC7D8CE4B0216877` です。

別プロセスで再ロードし、324購入状態、2161平方地形、540平方の道路・建物グリッド、1080平方樹木グリッド、遠端地形の復元と入力セーブ不変を確認しました。元100タイルセーブのSHA-256も `41C758DAF27D9768DF57ECB5FE28B2DBDC1772F0274BB95F6EF5CC365AF1AF63` のままです。

元の隔離MOD構成（31フォルダー、地形MODを含む485フックの起動確認）での結果です。最小構成ではBuildingLimitRemovalの保存用型がなく読み込めなかったため、保存に必要な元の構成を復元しました。大規模都市や任意のMOD構成の互換性を確認した結果ではありません。終了時には他MODのUnifiedUIのOnDestroy例外が記録されています。

遠端描画の追加検査では、道路・線路の高さマッピングがパッチ323を参照し、UV座標と高さ400mがネイティブ地形と一致しました。両ネットワークは表面テクスチャを使用しており、路面の欠けはまだ解消していません。

## 再現する検査

通常100の純粋ロジック検査に加え、以下で324の寸法・移行・保存検査を実行できます。

```powershell
dotnet run --project Checks -c Release -p:HundredTilesMapProfile=324
```

実ゲームの検証には購入済みゲームの正しいバージョンのアセンブリと、専用隔離環境が必要です。ゲームファイル・都市セーブ・プライベート検証ログは公開ソースに含みません。
試作の隔離環境を作成・復元する補助スクリプトは `IntegrationGame/Prepare-324Trial.ps1` です。先に通常の `Prepare.ps1` で専用ゲームを準備する必要があります。補助スクリプトは元のMODフォルダーをバックアップして、復元時にも試作フォルダーを削除せず保持します。進行中のCitiesプロセスがあれば変更を拒否します。
このブランチの既存リリース用ハッシュ一覧は、公開済み100タイル版の成果物を指します。324開発ビルドと一致するという表明ではありません。324のリリースDLL・リリース用ハッシュ一覧はまだ作成していません。
