# IPTのノードキャッシュ拡張（2026-10-13）

ユーザーのゲームログでは、道路作成・分割に伴うNetManager.ReleaseNodeから、IPT3のReleaseNodePostが配列範囲外を参照していました。IPT3は32768要素のノードキャッシュを直接参照します。More Network Capacity Renewの65024件のノードと併用すると範囲を超えます。導入されているIPT4の削除処理はすでに境界を確認しますが、読み込み用キャッシュは同じ32768要素であり、高いIDの保存統計を読み飛ばします。

対象DLLをSHA-256で限定したローカル修正ツールを追加しました。IPT3/4ともキャッシュの通常・エラー時の割り当てを65536要素（ushort IDの全範囲）へ変更します。IPT3の保存ループも65536要素を扱い、削除処理にnull・配列境界の確認を追加します。IPT4の既存の動的な保存ループと境界確認は変更しません。保存形式は既存のv003（Int32のノードID）を維持します。

- IPT3原版: `92E819A07CFD18C6E76D8A78F32BEDF54A0B091D0E49F2BA2F593F9444F17BBC`
- IPT3修正版: `6889FC97C243473E11C982BE0FFE0CC937FD9F47FD78156BB53AAD1C4BB290A1`
- IPT4原版: `0519E418B0DDB6A7AB8C717C12B3521B9A38DF7784D9C0E8B49BBB61D02502C0`
- IPT4修正版: `2EFE23119D2805F1CFF2DD793B867E8722CC71C1BDD749A4F84707A3A31C29B1`

原版IPT3のノード65000で例外を再現し、両修正版でnull・短いキャッシュの拒否と、ノード41・32767・32768・65023・65535の削除をCLRで検査しました。

ゲームを終了し、.NET SDKが利用できる環境で実行します。元DLLはゲーム外へバックアップし、未知の版は変更しません。

```powershell
./NetworkRenewPatcher/Apply-IptCacheRepair.ps1 -ModDll '<IPT3またはIPT4のDLL>' -GameManaged '<Cities_Data/Managed>'
```

この修正はノードキャッシュの範囲と保存対象のみです。IPT3/4の同時使用によるUIや同名の保存キーの競合を解消するものではありません。第三者DLLはHundredTilesの配布ZIPや公開ソースには含めません。Steamによる更新や整合性確認で原版に戻る場合は、対応版に対して修正を再適用してください。

実ゲームの隔離都市で、両修正版のキャッシュ初期化、実v003保存・読み込みメソッドによるノード65000の乗降統計37/11の保持、実NetManager.ReleaseNodeに取り付けた削除コールバックによる統計のクリアが合格しました。キャッシュ用のISerializableDataは検査専用のメモリ実装であり、都市の拡張保存領域には書き込んでいません。検査後にフィクスチャのHarmonyフック、静的キャッシュ、保存インスタンスを復元しています。これらはIPTの全機能やIPT3/4同時使用の保証ではありません。
