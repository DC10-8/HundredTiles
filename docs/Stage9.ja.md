# 第9工程：道路グリッドを参照するAIとツールの接続

第8工程で列挙したNetManager外の直接参照40本を、300×300の道路検索
グリッドへ接続する試験用変換を追加しました。各本体の269上限2箇所を299へ、
270行幅1箇所を300へ変更します。64mのセル幅と+135セルの座標原点を維持します。

## 対象

- 空港、キャンパス、公園、博物館、一般建物等の道路アクセス検索。
- Buildingのアクセスレーンと親ノード検索、BuildingToolの運河・歩道スナップ。
- NetToolの補助線、TransportToolの路線数、PathManagerの経路位置候補検索。
- 道路、鉄道、地下鉄、歩行者経路、航路、航空経路等のUpdateLanes。
- 地区の公園ノード・セグメント移動、災害の道路破壊、イベント、消防カバレッジ。
- ElectricityManager.ConductToNodes、WaterManager.UpdateGrid、ZoneBlock.CalculateBlock1、
  CanalAI.CheckBuildPositionの道路グリッド参照部分。

これらの系統の全処理を拡張したという意味ではありません。例えば電気・水道の
独自の供給グリッドや保存形式、地区や建物の別グリッドはまだ対応が必要です。
PathManagerで接続したのは道路上の経路位置候補検索です。

## 変更範囲の確認

40個の対象名を明示した一覧をPatchBuilderに保持します。ゲームDLLのハッシュに
加え、対象本体が道路グリッドを1回参照すること、上限2個・行幅1個だけを
含むことを確認します。上限の前後が「64で除算、135を加算、整数化、Min」で、
行幅が「行×幅＋列、ushort配列読み取り」に使われることを検査します。
この形と異なるILは変換せずエラーにします。
PathManagerの処理を委譲するオーバーロードは直接グリッドを参照せず、変換しません。

変換全体は158メソッド本体、709箇所になりました。
元の道路種類・レイヤー判定、経路接続、衝突・距離判定、ループとガード、
描画やサービス供給に関する命令はこの工程では変更していません。

## 検証

2026年10月10日にVerify.ps1の一括検証が成功しました。
対象ライブラリは警告0・エラー0でビルドされ、既存の地形・水流・資源・
保存・移行・巻き戻しの検証も通過しました。

NetConsumerChecksはゲームDLLの直接参照から対象40本を独立に列挙し、
各本体に変更が3箇所だけあることを確認します。
変更後の実ゲームILの上限計算80区間を300座標すべてで実行し、
配列検索40区間を90,000セルすべてで実行します。
既存領域と追加領域の検索先が同じ300列の配列に一致すること、
8640mと10560m付近の上限を確認します。

これは各AI・ツール・サービス本体の全体実行ではありません。
Unity上の建設、道路接続、供給、経路探索、ロード後の動作検証は残っています。

## 残る接続

[道路グリッド依存レポート](../reports/net-spatial-dependencies.csv)の55本は、
今回の外部参照40本、既存の部分変換11本、読込・再構築1本、未接続3本です。
未接続はNetManagerのEndRenderingImpl、CalculateGroupData、PopulateGroupDataです。
UpdateNodeRenderer等の直接配列参照を持たない描画座標変換も対応が必要です。
描画グループの45×45構造と他Managerとの整合を取る作業が残ります。
この一覧はローカルAssembly-CSharp.dll内の直接参照であり、
他DLL・他MOD・間接依存の網羅を保証するものではありません。

建物・樹木・地区・サービス等の空間グリッド、樹木の座標表現と保存、
地形・水面描画、カメラ、エディター境界、MOD競合検出と実ゲーム検証も
引き続き残っています。CanActivateはfalseのままで、自動導入も行っていません。
