# 地形・水流拡張に向けた監査と試験基盤

## 今回の成果

Assembly-CSharp.dll内の22,758個のmanagedメソッド本体を走査し、
3,066件の固定値候補と86,062件の関連参照を記録しました。
`reports/manifest.json`にアセンブリSHA256、MVID、関連メソッドのILハッシュを記録しています。
`constants.csv`はメタデータトークンとILオフセット付き、`references.csv`は参照先付きです。
メソッドのオーバーロードはトークンで区別できます。
これは対象アセンブリの静的数値／参照監査であり、全ゲーム依存関係の意味解析の完了ではありません。
シェーダー、他のアセンブリ、実行時計算で作られる定数は別途調査が必要です。
数値候補の自動書き換えは行いません。

## 確認した変更点

| 処理 | 変更方針 |
| --- | --- |
| TerrainManager.Awake | 高さ配列を1,442,401要素、表面を1,440,000セル、地形パッチを100要素へ。LOD boundsの各階層も整合させる |
| TerrainPatchの生成／Refresh | グリッド数、ストライド、セル上限は拡張する。既存座標用の半幅8,640mは維持する |
| WaterSimulation.Awake | 両水流バッファを1,442,401要素、パッチ用の高さ／表面マップ／boundsを100要素へ |
| WaterSimulation.UpdatePatch | パッチインデックスの9を10へ、半解像度の540を600へ |
| WaterSimulation.SimulateWater | 解像度、パッチ進捗、パッチインデックス、表面範囲を一貫して変更。水源の座標オフセットは8,640mを維持 |
| FillHeightMap／FillSurfaceMap | 1200セル・1201ストライドと新しい上限を反映 |
| Data.Serialize／Deserialize | 標準データと拡張データの読み書きを分離。旧保存配列を拡張するタイミングを統一 |

### 水のビットマップ

標準の`m_bitCells=17`では新しい最終頂点1200のビット位置が70となります。
C#のulongシフトはシフト数を下位6ビットに制限するので、
範囲超過は離れた位置の水の誤検出を招きます。
64×64ビットマップを維持する試験設計では、1ビット当たり19セルが必要です。
1200 / 19 = 63となり、端の頂点まで範囲に収まります。
`WaterGrid.cs`に座標・ビット位置計算と水バッファ移行を実装しました。
粒度変更後は全ビットマップを再構築する必要があります。実際のゲーム接続は未実装です。

### 原点を保持する拡張

元の地形と道路を維持するため最小座標は-8,640mです。
解像度を1200にして幅の半分を9,600mへ単純変更すると、
水源や描画パッチが元の都市から960mずれます。
幅と座標原点を別の値として扱う必要があります。
1200個のセルと端点を含む1201個の頂点も区別します。

### 水流の初期化順

TerrainManager.Awake内でWaterSimulationをAddComponentし、
WaterSimulation.Awakeがバッファ作成と水流スレッドの開始を行った後で、
TerrainManagerが高さバッファをInitializeに渡しています。
OnLevelLoadedで配列を交換する方式は、このスレッドと既存の読み取りロックに競合します。
拡張パッチはAwake実行前に導入するか、ロード時停止状態と読み取りロックの排出を
確認して全関連配列をまとめて交換する必要があります。
診断MODは配列の長さだけを読み取り、配列交換やパッチ適用をしません。

## 診断用MOD

`Diagnostics/bin/Release/net35/HundredTiles.Diagnostics.dll`をビルドしました。
IUserMod／LoadingExtensionBaseを実装したゲーム読み込み用の診断MODです。
**100タイル化を有効にするMODではありません。**
マップ読み込み後にゲームバージョン、SHA256、地形・所有・水流配列の実サイズを出力します。
出力先は`%LOCALAPPDATA%\Colossal Order\Cities_Skylines\HundredTilesDiagnostics`です。
他のMODによって変更された実サイズを静的監査結果と照合できます。

手動試験ではゲームを終了してから、DLLを
`%LOCALAPPDATA%\Colossal Order\Cities_Skylines\Addons\Mods\HundredTilesDiagnostics`
へ置き、コンテンツマネージャーで有効にして都市を読み込みます。
読み込み完了後に出力ファイルとゲームログを確認します。
この開発作業ではゲームへの配置・起動は実施していません。

## 検証

`Verify.ps1`で再現できます。

- .NET 3.5向けCoreと診断MODが警告0・エラー0でビルド。
- 全100区画、所有情報、全1,442,401頂点の地形移行を検証。
- 全1201個の水流ビット座標とworld/raw往復を検証。
- 水バッファの全1,442,401位置と総量保持を検証。新規領域は初期値0。
- 監査ツールを専用fixtureで検証。整数／float／短い定数／配列生成／呼び出し参照／IL switchテーブルを確認。
- 実ゲームアセンブリ全メソッドのILデコードが成功。

ゲーム内の診断MOD実行、地形描画、水流更新、建設、保存と再ロードは未検証です。
水移行の総量テストは移行処理の検証で、ゲームの水流アルゴリズム検証ではありません。
