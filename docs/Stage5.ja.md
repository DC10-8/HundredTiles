# 第5工程：100区画の所有情報と購入判定

所有情報の保存・復元、区画番号、購入判定、所有表示の接続を追加しました。
実行中のゲームへの適用と有効化は引き続き行っていません。

## 保存・復元

`HundredTiles.Ownership.v1`に100区画の購入順、所有数、開始区画を
516バイトで保存します。形式バージョン、SHA-256、標準所有データの
指紋、同時保存した地形・水流全データのSHA-256を含みます。

標準のGameAreaManager.Dataには中央5×5を投影します。外側の購入を
除いた購入順は1から連続する値に詰め直します。開始区画が外側なら
投影内で最初に購入した区画、投影内に所有がなければ標準開始区画を使います。
元の100区画の情報は専用データから復元します。

標準Deserializeには25要素のscratchを渡し、読了後に100要素の
既存配列へ移行します。専用データは全ManagerのUpdateDataより前に
検証・復元し、所有配列の参照を保ちます。

地形・水流と所有データは同じ保存処理で公開し、保存失敗時には
両方を以前の状態へ戻します。片方だけある場合や組み合わせが異なる場合は
復元を拒否します。過去の開発工程で作った地形・水流だけの実験データも
拒否対象です。専用データが両方ない標準セーブは中央5×5として移行します。

## 購入・区画

- 最大所有数100、10列の区画番号と隣接判定。
- 9区画までは標準の解放条件を維持。9区画取得後の追加購入では
  存在しないマイルストーンを照会しません。
- AreasWrapper.OnCanUnlockAreaを維持し、他MODの拒否を反映。
- UnlockArea本体は維持し、通知、9区画の実績、失敗時の所有巻き戻しを保持。
  10列の番号、旧原点を維持した購入範囲、詳細地形パッチ番号へ変換。
- 初期100要素、開始区画44、詳細地形復元時の余分な2区画オフセットを除去。
- 所有テクスチャ16×16、更新ループ、表示用座標とシェーダーの
  テクスチャ写像、ゲームプレイ側の所有表示範囲を接続。

## 検証と限界

レビュー済みIL変換は合計76メソッド本体・407変更です。
浮動小数点の変更もビット値で固定し、元アセンブリと各メソッドの
ハッシュを検査します。6つの保存メソッドで12箇所のヘルパー挿入を検証します。

本番の保存フックと購入判定をモックManagerで実行し、100区画の保存復元、
標準投影、不正購入順、異なる保存データの組み合わせ、欠落データ、
保存失敗時の巻き戻し、解放条件、隣接購入、コールバック拒否を検証します。
隣接購入を繰り返して100区画に到達することも検査します。

購入価格の資源・道路集計、建設・サービス等の空間グリッド、
エディター側の固定境界、RayCast・カメラ・ツール、競合検出は残ります。
Unity上の実際の購入、描画、建設、保存再ロードは未検証です。
この工程はプレイ可能な100タイルMODの完成を意味しません。
`CanActivate`はfalseのままです。
