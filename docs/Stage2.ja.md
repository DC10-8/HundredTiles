# 第2工程：地形・水流・描画の試験用Harmony変換

## 状態

具体的なHarmony transpilerと対象ゲーム版に固定した変更計画を実装しました。
**実行中のゲームへのパッチ適用、100タイルの購入・建設、保存／再ロードは未実装・未検証です。**
今回の成果物は試験用パッチライブラリです。IUserModや自動適用処理はありません。
`PatchPlan.CanActivate`はfalseであり、この計画単体では100タイル化を有効にできません。
ゲーム本体のDLLを書き換えたり、MODフォルダーに配置したりしていません。

## 実装した変更

`ExperimentalPatch/ReviewedPlan.tsv`に16メソッド・98命令の変更を記録しました。
元の命令数、メタデータトークン、メソッドILのSHA256とゲームアセンブリSHA256を持ちます。
命令オフセットではなく命令の順序番号を使い、HarmonyのCodeInstructionへ変換します。
計画生成ツールも監査済みアセンブリ以外では計画の再生成を拒否します。

| 対象 | 変更 |
| --- | --- |
| TerrainManager.Awake | raw高さと表面の配列、undo配列、パッチ／bounds配列、初期化ループを拡張 |
| TerrainManager.OnDestroy | 追加パッチまで破棄対象にする |
| EndRenderingImpl／BeginOverlayImpl | 100パッチの描画、水流更新フレーム、オーバーレイ走査 |
| GetSurfaceMapping／GetHeightMapping／GetWaterMapping | 最終パッチ番号9、インデックス用ストライド10へ |
| UpdateBounds／GetBounds | bounds階層の最細格子144→160、各階層の基準9→10、rawストライド1201へ |
| TerrainPatch生成／Refresh | rawセルの上限、表面上限、頂点ストライドを変更 |
| WaterSimulation.Awake | 水流バッファ1201²、マップ100枚、ビット粒度19へ |
| UpdatePatch／SimulateWater | パッチストライド10、表面半解像度600、進捗100へ |
| FillHeightMap／FillSurfaceMap | raw解像度1200へ |

この表は今回の対象範囲であり、これだけでゲーム全体の整合性が取れるという意味ではありません。
LOD boundsの格子幅は9×2⁴=144から10×2⁴=160へ変更します。
undo配列は3×1201²+1=4,327,204要素です。
タイル内の地形解像度480、テクスチャサイズ128／512は維持します。

### 水源の座標原点

SimulateWaterでは1200セル×16mから幅を求めると、幅の半分が9600mになります。
しかし既存の都市座標を維持する設計の原点オフセットは8640mです。
今回の計画では、幅計算に使うローカル変数のロード1箇所を1080の定数へ置き換え、
座標用の幅を17280mに維持します。シミュレーションのセル走査は1200へ拡張します。
この箇所は元の命令列を照合してから変更し、他の幅計算には一括置換を行いません。
TerrainPatch等にある17280fも、この段階では既存の座標原点を維持する目的で変更しません。

## 拒否条件と入力の保持

変換入口でゲームアセンブリと対象メソッドのハッシュを照合します。
命令数、各置換位置の元定数／ローカル変数番号が異なる場合は例外を返します。
計画中の全置換を検証してから、新しい命令リストを作ります。
入力リストを直接書き換えず、Harmonyのラベルと例外ブロックをコピーして維持します。
誤ったゲーム版の計画生成も拒否します。
これらは変換の検証であり、パッチのインストールとロールバック機構はまだありません。

## ビルドと検証

```powershell
./Verify.ps1
```

Core／診断MODに加え、ExperimentalPatchを.NET Framework 3.5向けにビルドします。
PatchBuilderとPatchChecksは.NET 10を使います。
Mono.Cecilは手元のilspycmd 10.1.0.8386に含まれるDLL、Harmonyは既存開発環境の
CitiesHarmony.Harmony.dllを参照します。これらの参照先はプロジェクトファイルに記載しています。
別環境でビルドする場合は参照先の設定が必要です。

実ゲームアセンブリをCecilで読み取り、HarmonyのCodeInstructionへ変換してテストしました。
ゲームの型をロードしたり、ゲームの初期化や水流スレッドを起動したりしていません。

- 16メソッドの元のILハッシュと命令数を照合。
- 98箇所の変換結果を検証。
- 計画外の命令・全分岐ラベル・例外処理マーカーの保持を検証。
- 元の命令リストが変更されないことを検証。
- 各メソッドに対し、命令不一致と命令数不足の拒否を検証。
- 水流のセル数拡張と座標原点維持の両方が計画に含まれることを検証。
- 不正な計画レコードと未対応のcoverage宣言を拒否。

実際のMonoでのパッチ適用、ILの最終コンパイル、描画や水の動きは未検証です。
命令変換テストの成功をゲーム内の正常動作と同一視することはできません。

## 次に接続する処理

最優先は旧データ読み込みと拡張後データの保存を整合させることです。
現在のAwake拡張だけを適用すると、標準Deserializeが拡張後の配列長だけデータを読むため、
旧セーブの読み込みを壊します。このため適用入口は作っていません。

併せて、TerrainManagerの残りのサンプリング・地形編集・SimulationStep、
Data.AfterDeserialize、詳細地形のスロット数、TerrainModify／TerrainArea／描画補助、
道路や建物などの空間グリッドを接続する必要があります。
所有100区画への接続と新規領域のサービス・経路探索は引き続き未実装です。
